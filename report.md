### 1. Вибір хостингу та обґрунтування
Для розгортання вебдодатку було обрано хмарну платформу **Render.com**.

**Обґрунтування вибору:**
1. **Підтримка Docker із коробки:** Платформа автоматично виявляє `Dockerfile` у репозиторії та збирає додаток у контейнері, що виключає проблеми з несумісністю версій Node.js або системних бібліотек.
2. **Безкоштовний тариф (Free Tier):** Render пропонує безкоштовні ресурси для хостингу Web Services, чого цілком достатньо для навчальних цілей та демонстрації роботи вебдодатків.
3. **Автоматичний CI/CD:** Будь-які зміни, надіслані (push) у гілку `main` на GitHub, автоматично запускають процес повторного збирання (redeploy) та оновлення сайту без ручного втручання.
4. **Простота налаштування:** Інтуїтивно зрозумілий інтерфейс підключення репозиторіїв та інформативна консоль логів під час складання контейнера.

### 4. Висновки
Під час виконання лабораторної роботи було успішно розгорнуто Node.js/Express вебдодаток у хмарному середовищі Render.com з використанням контейнеризації Docker.

**Чого навчилися:**
- Налаштовувати базовий вебсервер на Node.js та Express для віддачі статичних файлів та обробки динамічних API запитів.
- Створювати конфігураційні файли `Dockerfile` та `.dockerignore` для правильного та ефективного пакування додатку у легковажний Alpine-контейнер.
- Пов'язувати репозиторій на GitHub із хостингом Render.com для забезпечення автоматизованого CI/CD конвеєра розгортання.
- Аналізувати логи збирання та роботи сервера в реальному часі через хмарну консоль.

**Виниклі труднощі:**
- Первинна конфігурація збирання Docker вимагає чіткого дотримання копіювання файлів залежностей (використання `npm ci --only=production` замість `npm install` для економії простору та підвищення надійності).
- Безкоштовний тариф Render має особливість «засинати» (cold start) після 15 хвилин бездіяльності сайту, через що перший запит до додатку після паузи може тривати близько 50 секунд. Цю особливість було враховано, додавши індикатор завантаження на фронтенді.
